# Agent Instructions

## Repo Overview

npm workspaces monorepo with two packages:

| Package | Stack | Port |
|---------|-------|------|
| `api/` | Hono + Zod OpenAPI + Prisma + SQLite | 3000 |
| `web/` | React 19 + Vite + TailwindCSS v4 + React Query | 5173 |

## Essential Commands

```bash
# Install all dependencies
npm install

# Start both API and web concurrently (web waits for API health check)
npm run dev

# Start individually
npm run dev:api
npm run dev:web

# Type-check all workspaces
npm run typecheck

# Build all workspaces
npm run build
```

## Code Generation (run after schema or API changes)

```bash
# Regenerate Prisma client + export openapi.json
npm run generate --workspace api

# Regenerate Orval hooks from api/openapi.json
npm run generate --workspace web

# Regenerate everything
npm run generate
```

**Order matters:** always regenerate the API first, then the web.

## API Architecture (`api/src/`)

- **`app.ts`** — all routes defined here using `@hono/zod-openapi`. Add new routes in this file.
- **`db.ts`** — singleton Prisma client (do not instantiate `PrismaClient` elsewhere).
- **`index.ts`** — server entry point.

### Adding a new endpoint

1. Define Zod schemas in `app.ts` (input + response), marking them `.openapi('SchemaName')`.
2. Create a route with `createRoute(...)`.
3. Register it with `app.openapi(route, handler)`.
4. Run `npm run generate` to export the updated OpenAPI spec and regenerate the web client.

### Database changes

1. Edit `api/prisma/schema.prisma`.
2. Run `npm run prisma:sync --workspace api` to apply changes to the SQLite file.
3. Run `npm run generate --workspace api` to regenerate the Prisma client.

The SQLite database lives at `api/data/workshop.db`. Delete it and restart to reset all data.

## Web Architecture (`web/src/`)

- **`api/`** — auto-generated Orval hooks (do **not** edit manually).
- **`App.tsx`** — main app component; import generated hooks here.
- Vite proxies `/api` → `http://localhost:3000` in dev. Override with `VITE_API_BASE_URL` for production builds.

## TypeScript

- Both workspaces use **ESM** (`"type": "module"`).
- Use `.js` extensions on relative imports in `api/` (TypeScript ESM requirement).
- Run `npm run typecheck` before committing; the build will fail on type errors.

## Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `API_PORT` | `3000` | API listen port |
| `CORS_ORIGIN` | `http://localhost:4173,http://localhost:5173` | Comma-separated allowed origins |
| `VITE_API_BASE_URL` | _(empty, uses Vite proxy)_ | API base URL for production web builds |

## Common Pitfalls

- **Never edit files in `web/src/api/`** — they are generated by Orval and will be overwritten.
- **Run `npm run generate` after any schema or route change** before touching the frontend.
- Prisma client must be generated before the API can start (`npm run generate --workspace api`).
- No test suite exists yet; validate changes with `npm run typecheck` and manual smoke testing.
